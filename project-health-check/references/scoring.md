# 评分规则

本文件在 check_quality.py 执行后被 LLM 条件加载，用于解读评分结果。

---

## 评分维度

| 维度 | 权重 | 说明 |
|------|:----:|------|
| 函数长度 | 20% | 函数平均行数，越短越好 |
| 行长度 | 10% | 单行最大字符数 |
| 文档覆盖 | 20% | 函数/类是否含 docstring |
| 类型注解 | 15% | 函数参数/返回值是否有类型 |
| 注释比例 | 10% | 注释行 / 总代码行，适中最优 |
| TODO/FIXME | 5% | 未完成标记数量 |
| 导入规范 | 10% | import 是否分组、是否有 `*` 导入 |
| 文件结构 | 10% | `__init__.py` 是否存在、目录组织 |

## 评分标准

| 分数 | 等级 | 含义 |
|:----:|:----:|------|
| 90-100 | A | 优秀，代码规范良好 |
| 75-89 | B | 良好，少量改进空间 |
| 60-74 | C | 及格，存在明显问题 |
| 0-59 | D | 不及格，需要重点改进 |

## 分数触发逻辑

- 得分 ≥ 75 → 仅输出评分，给出简要建议
- 得分 < 60 → **必须加载 `remediation.md`**，逐条给出修复方案
- 所有场景 → 输出各维度分数明细
